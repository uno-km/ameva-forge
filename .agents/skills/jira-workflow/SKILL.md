# Jira 기반 개발·검증 실시간 동기화 워크플로우 (Jira Development Workflow)

## 📌 핵심 기본 원칙 (Mandatory Rules)

1. **지라 티켓 기반 작업 원칙**:
   - 모든 개발, 버그 수정, 리팩토링, 테스트 및 인프라 구축 작업은 **반드시 Jira에 등록된 티켓(`SCRUM-XX`)에 기반하여 1:1로 진행**한다.
   - 사전에 등록되지 않은 작업이나 범위 외의 임의 작업은 절대 임의로 수행하지 않는다.

2. **작업별 실시간 진행 상황 기록 (Real-time Documentation)**:
   - 각 서브태스크를 시작할 때: 작업 목표 및 착수 사실을 기록한다.
   - 코드 수정 완료 시: **어떤 파일을 어떻게 수정했는지(수정 내역 및 변경 사유)** 상세히 기술한다.
   - 테스트 실행 완료 시: **단위 테스트, Playwright WebGPU E2E 테스트 수치(Loss, VRAM Byte, Pass/Fail 여부)**를 Jira 코멘트에 그대로 기록한다.
   - 해당 티켓의 상태를 `Done` 또는 진행 상태로 전환한다.

3. **추가 요구사항/범위 변경 시 사전 승인 (Approval Gate)**:
   - 기존 등록된 28개 태스크 외에 추가적인 작업이나 설계 변경이 필요할 경우:
     1. 즉시 사용자에게 상황을 보고한다.
     2. 신규 Jira 티켓을 생성/발급받는다.
     3. 사용자의 명시적 허가를 득한 후에만 개발에 착수한다.

4. **보안 및 자격증명 격리 원칙**:
   - Jira API Token, 이메일, 연동 스크립트는 Git 저장소에 절대 커밋하지 않으며, 로컬 격리 경로(`scratch/`)에서만 안전하게 실행한다.
